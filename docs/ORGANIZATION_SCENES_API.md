# 组织场景只读访问

拥有直接分配的 `manager` 或 `admin` 角色且属于至少一个组织的用户，可以查看其所在组织全部成员创建的场景，包含未公开场景。组织通过当前数据库中的 `user_organization` 与 `organization` 判断；多组织取并集，不重复返回场景。组织成员关系不是协作编辑关系，不会赋予编辑、删除、发布或资源写入权限。

## 列表

`GET /v1/verses/organization`

需要 JWT。支持与全局场景列表相同的 `VerseSearch[...]`、`authorId`、`authorSearch`、`propertyId`、`tags`、`public`、`sort`、`page`、`per-page`、`expand` 和 `fields`。默认按 `id` 降序，每页最多 100 条；响应复用场景数组和 `X-Pagination-*` 分页头。客户端传入组织 ID 或全局 scope 不会扩大授权范围；作者、公开属性及标签筛选只会缩小结果。

无 `manager` / `admin` 直接角色或无有效组织成员关系返回 `403`；未认证返回 `401`；无效搜索与分页参数返回 `400`。`root` 单凭继承角色不获得此入口，root 的既有全局列表保持原规则。

## 详情与预览

`GET /v1/verses/organization/{id}`

支持标准 `expand`，每次请求重新判断当前用户与场景作者是否共享有效组织。不存在或组织外的场景返回 `404`，组织外公开场景也不属于该专属入口。

同组织 manager 或 admin 也可通过标准 `GET /v1/verses/{id}` 读取场景详情、空间、脚本和预览所需的关联数据；其 `viewable=true`。组织外私有场景仍返回 `403`。公开场景的既有标准读取权限不变。

`editable` 保持原作者及协作组规则：同组织身份本身不产生编辑权限。前端组织场景入口与预览强制只读，包含当前用户自己的场景；用户已有的本人及协作编辑权限仍可在原有入口使用。此功能不修改场景归属、公开属性，不扩大任何写权限。

两个组织端点只接受 `GET`、`HEAD` 和 `OPTIONS`，不提供写操作；移除组织关系后，下次请求立即失去相应组织阅读权限。

旧 `system/take-photo` 与 `snapshot/take-photo` 端点同样要求场景 `editable=true`，防止只读用户创建或覆盖发布快照；有效但不存在的场景返回 `404`，无编辑权限返回 `403`，无效或数组形式的 `verse_id` 返回 `400`。作者与原协作者的快照发布权限保留。
